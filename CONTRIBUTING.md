# 🤝 Contribuindo para NFiles IA

Obrigado por considerar contribuir para o NFiles IA! Este documento fornece diretrizes e instruções para contribuir.

## Código de Conduta

Nosso projeto e comunidade se dedicam a proporcionar um ambiente acolhedor e inspirador para todos. Leia nosso [Código de Conduta](CODE_OF_CONDUCT.md) e comprometam-se em segui-lo.

## Como Contribuir

### 🐛 Relatar Bugs

Antes de criar relatórios de bugs, verifique a [lista de issues](../../issues) já que você pode encontrar um que cubra seu problema.

**Como enviar um bom relatório de bug:**
- Use um título descritivo
- Descreva os passos exatos que reproduzem o problema
- Forneça exemplos específicos para demonstrar as etapas
- Descreva o comportamento observado e qual era o comportamento esperado
- Inclua capturas de tela se possível (remova dados pessoais)
- Mencione sua versão do Windows e versão do NFiles IA

**Template de Bug:**
```
## Descrição
Descrição clara e concisa do bug.

## Passos para Reproduzir
1. Vá para '...'
2. Clique em '...'
3. Veja o erro '...'

## Comportamento Esperado
Descreva o que deveria acontecer.

## Ambiente
- Windows: [10/11]
- NFiles IA: [versão]
- RAM: [quantidade]
```

### 💡 Sugerir Melhorias

Melhorias são sempre bem-vindas! Siga estes passos:

1. Use um título claro e descritivo
2. Forneça uma descrição detalhada da melhoria sugerida
3. Liste alguns exemplos de como essa funcionalidade seria útil
4. Mencione outras aplicações que tenham recursos similares

### 📝 Melhorar Documentação

Documentação é tão importante quanto código! Se encontrar algo que possa ser melhorado:

1. Corrija erros de digitação
2. Esclareça instruções confusas
3. Adicione exemplos práticos
4. Traduza para outros idiomas (português, inglês, espanhol)

## Processo de Pull Request

1. **Fork o repositório** e crie uma branch com um nome descritivo
   ```bash
   git checkout -b feature/descricao-da-melhoria
   ```

2. **Faça suas alterações** e teste bem

3. **Commit com mensagens claras**
   ```bash
   git commit -m "Adicionar: descrição da alteração"
   ```

4. **Push para seu fork**
   ```bash
   git push origin feature/descricao-da-melhoria
   ```

5. **Abra um Pull Request** com uma descrição completa do que foi alterado

### Padrões de Commit

Use prefixos nas suas mensagens de commit:
- `Fix:` para correções de bugs
- `Adicionar:` para novas funcionalidades
- `Docs:` para mudanças de documentação
- `Refactor:` para refatoração de código
- `Style:` para formatação e style
- `Test:` para testes

Exemplo:
```
Fix: corrigir crash ao processar arquivos grandes

Descrição detalhada da mudança.
Mencionar issue relacionada: #123
```

## Labels nas Issues

| Label | Significado |
|-------|-------------|
| `bug` | Algo não está funcionando corretamente |
| `enhancement` | Nova funcionalidade ou melhoria |
| `documentation` | Melhorias na documentação |
| `good-first-issue` | Bom para começar a contribuir |
| `help-wanted` | Ajuda ativa necessária |
| `priority-high` | Urgente/crítico |
| `priority-low` | Pode ser deixado para depois |
| `question` | Pergunta que precisa de esclarecimento |

## Diretrizes de Estilo

### Português Claro
- Use português correto e claro
- Evite jargão desnecessário
- Mantenha parágrafos concisos

### Markdown
- Use headings apropriados (# ## ###)
- Destaque código com backticks
- Use listas para melhor legibilidade
- Adicione links quando relevante

### Screenshots e GIFs
- Remova informações pessoais antes de compartilhar
- Use ferramentas como Sharex ou Gyazo
- Mantenha qualidade alta

## Processo de Review

1. Um mantenedor revisará sua PR em até 5 dias úteis
2. Alterações podem ser solicitadas
3. Após aprovação, seu PR será mergeado
4. Seu nome será adicionado aos créditos
